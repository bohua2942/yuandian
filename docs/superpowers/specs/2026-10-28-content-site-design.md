# 内容源网站设计

用户已选择同时实现 DecoHack 风格页面，以及每日采集、翻译和更新。沿用上一轮提出的 Next.js、Python、文件内容库、GitHub Actions、Vercel 方案。当前目录为空，开发在本目录独立进行。

## 体验与范围

- 临时站名「源点 DAILY」，替换 DecoHack 品牌；复刻米灰底、白色卡片、蓝紫色日期、榜单与右侧栏目布局。
- 首页、PH/HN/AI 栏目、按日期归档、内容详情、周刊（人工编辑）、搜索、RSS、深浅色与移动布局。
- 首版无账号、支付、数据库或网页管理后台。周刊通过内容文件维护。
- 所有条目保留原文链接、来源、实际采集时间与翻译状态。没有中文翻译时显示原文及标记。

## 数据与自动化

- Python 3.12+；PH 使用官方 GraphQL（需要 token），HN 使用官方 Firebase API，AI 早报读取配置中的公开 RSS。
- Node.js 22+，Next.js 16 / React 19，静态导出；浏览器不接触任何模型或 PH 凭据。
- 内容为 content/catalog.json，原始采集与日志在忽略的本地 data/ 中。模型通过 OpenAI 兼容接口调用；密钥仅 .env.local 或 GitHub Secrets。
- 定时：北京时间每天 09:17（UTC 01:17）；实际触发可能延迟。PH 收集上一个完整 UTC 日的榜单，其他栏目是运行时快照。每页显示栏目自己的实际日期。
- 用户已确认自动更新网站，API 密钥稍后本地填写。工作流采用自动发布模式；本地 --draft 可仅生成草稿。本次交付不创建远程仓库或激活线上任务。
- 同一天同来源 ID 只存一次；跨 RSS 去除跟踪参数后去重；跨日期保留历史。相同原文复用已验证翻译。
- 模型输出只能提供标题、摘要、标签，不得改来源 ID/链接/分数；输出缺项、空中文、非法 JSON 均拒绝发布该来源。
- 网络与翻译失败保留该来源上次成功内容。成功来源可独立更新，失败状态及工作流失败均可见；不生产假内容填充。
- 未提供模型密钥时可显式运行 --collect-only 抓取真实原文供接入检查，但不冒充完成中文自动发布。

## 验收

1. 单元/集成测试覆盖重复运行、跨日历史、来源局部失败、翻译失败/ID 不匹配、原文保留、API/订阅格式。
2. 实际抓取公开 HN 与 RSS，记录数量与时间；PH 和模型 API 必须有用户凭据才能声称验证成功。
3. Next 生产构建与类型检查通过；本地浏览器验证桌面、手机、搜索、主题、归档、详情和 RSS。
4. 交付本地启动入口、中文说明、环境变量样例、CI 工作流与部署说明。线上部署与定时激活的状态须与真实结果一致。

## 接入边界

PH 商业用途需要依照其官方 API 条款确认授权。开源采集脚本 MIT 许可不等于数据商业许可；本站不复制对方 logo 或存量文章。
